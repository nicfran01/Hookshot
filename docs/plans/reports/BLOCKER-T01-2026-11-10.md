## What the task asked

Step 6 and the acceptance criterion `ls .github/workflows` (`source-regressions.yml`, `linux-appimage.yml`,
three `*.disabled`): rename `release.yml`, `windows-builder.yml` and `vulkan-dlss.yml` to `*.yml.disabled`,
and remove only the `release` job from `linux-appimage.yml`. "Files to touch" does not include any file under
`tests/`. The plan (`03-architecture.md` §7) gives the same instruction.

## What was found

- **verified:** an upstream game-free test reads `windows-builder.yml` by path.
  `git show upstream/main:tests/test_recomplauncher_json.py`, line 31, `test_windows_zip_carries_it`:
  `(ROOT / ".github" / "workflows" / "windows-builder.yml").read_text(...)`, then asserts two strings in it.
  Renaming the file makes that test fail with `FileNotFoundError` in `tests/run_all.py`, and so in the fork's
  `source-regressions.yml` CI, which the task keeps on purpose.
- **verified:** no test reads `release.yml` or `vulkan-dlss.yml`
  (`git grep -nE 'release\.yml|vulkan-dlss' upstream/main -- tests 'nx2/test_*.py'` prints nothing).
- **verified:** two tests read `linux-appimage.yml`, but only its `appimage` job:
  `tests/test_appimage_package_retry.py:43` (the "System packages" step) and
  `tests/test_appimage_player_build.py:78` (`appimage.sh` runs before `check_player_build.sh`). Removing the
  `release` job (from line 136 to the end of the file in `upstream/main`) keeps both.
- **verified:** `windows-builder.yml`'s own `release` job is already off unless a repository variable turns it on:
  `if: startsWith(github.ref, 'refs/tags/') && ... && vars.CI_RELEASE_WINDOWS == 'true'` (line 207 in
  `upstream/main`). Its other jobs (`package`, `vulkan`) upload workflow artifacts only. Tags come from
  `release.yml` (semantic-release on `main`), which is disabled in this task anyway.
- **inferred:** the plan's rename-only approach was written without checking which workflow files the tests read.

## What was tried

Only read-only checks and the non-destructive start of step 3: `git init -b main`, the two remotes
(`upstream` push set to `DISABLED`), `git fetch upstream`, `git fetch origin`. The planning `.gitignore` was moved
aside for step 2, then moved back. No reset, no checkout, no file of the working tree changed, nothing committed.

## Options

1. **Keep `windows-builder.yml` at its path and remove only its `release` job**, the same treatment as
   `linux-appimage.yml`. Two `*.disabled` files instead of three. Cost: one edit to the task file and §7. Risk: its
   `package` and `vulkan` jobs still run on push in the fork (Windows runner minutes; artifacts only, nothing
   published). Merge risk: a conflict only when upstream edits that job.
2. **Rename it as written and change the test** to read `windows-builder.yml.disabled` when the `.yml` is absent,
   marked `(raiders)`. Cost: an edit to an upstream test, outside T01's files. Risk: a merge conflict whenever
   upstream edits that test, and an exception to "shared files only gain a lookup".
3. **Keep it at its path and limit its triggers to `workflow_dispatch`** (and remove the `release` job). No Windows
   builds on push. Cost: two edits to the file. Merge risk: higher than option 1 (the `on:` block changes upstream
   too).

## Recommendation

Option 1. It meets the plan's aim (a fork must not publish under upstream's release scheme), keeps every upstream
test passing without touching `tests/`, and is the smallest change to a shared file. The acceptance line becomes:
`ls .github/workflows` shows `source-regressions.yml`, `linux-appimage.yml`, `windows-builder.yml` and two
`*.disabled` (`release.yml.disabled`, `vulkan-dlss.yml.disabled`). If Windows CI minutes matter, use option 3.

## Resolution (same day)

The user chose option 1. While applying it, option 1 turned out to be wrong as well: **verified** by
`grep -n 'Windows-x64.zip' .github/workflows/windows-builder.yml`, the string `dist/Hookshot-*-Windows-x64.zip`
that `test_windows_zip_carries_it` asserts is only in the `release` job (upstream line 242), so removing that job
fails the same test. The claim above that option 1 "keeps every upstream test passing" was **inferred**, not
checked. The user then chose to keep the job and guard its `if:` with `github.repository == 'NotRexed/Hookshot'`.
T01 was completed that way; see `upstream-sync.md`, "Deviations".
