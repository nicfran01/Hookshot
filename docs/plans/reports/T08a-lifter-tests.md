# T08a · Lifter differential tests on Linux, run on Raiders (2026-11-10)

Both of the lifter's differential tests now build and run on Linux, and both pass on Raiders on the Steam Deck: every
instruction form the game uses, and random whole functions and call trees, against Unicorn. Before this task the
harnesses were Windows only, so neither had ever run on Raiders (T02). No lifter change was needed, and `third_party/`
is unchanged.

Every claim is **verified** (the command, file or log line named) unless marked otherwise. Logs are in
`~/raiders/work/t08a_*.log` on the Deck (not fetched or committed).

## The POSIX code paths

| Where | Windows (unchanged) | POSIX (added) |
|---|---|---|
| `nx2/test_leaf.py` `HARNESS`, includes | `#include <windows.h>` | `#else`: `<setjmp.h>`, `<signal.h>`, `<string.h>`, `<sys/mman.h>`; `MAP_FIXED_NOREPLACE` defined as `0x100000` when the headers lack it |
| `HARNESS` `run()` | `__try { … } __except (EXCEPTION_EXECUTE_HANDLER) { return GetExceptionCode(); }` | `sigsetjmp`, with a handler for `SIGSEGV`, `SIGBUS`, `SIGILL` and `SIGFPE` installed once by `sigaction` with `SA_ONSTACK` on a 64 KB `sigaltstack`. The handler `siglongjmp`s back, and `run()` returns the Windows code of the same kind: `0xC0000005` (SEGV, BUS), `0xC000001D` (ILL), `0xC0000094` (FPE). The Python side treats any non-zero code as a failing case (`"halted %d fault %#x"`), so each code keeps its meaning |
| `HARNESS` `main()` | `VirtualAlloc(A64_PTR(IMG_BASE)…)` → `return 3`; the same for the scratch → `return 4` | `mmap(A64_PTR(…), …, PROT_READ \| PROT_WRITE, MAP_PRIVATE \| MAP_ANONYMOUS \| MAP_FIXED_NOREPLACE, -1, 0)`, with the same 3 and 4 when the address is not the one asked for |
| `nx2/test_insn.py` (wrapping `third_party/a64-kit/tests/insn_test.py` `build_harness`, which is not edited) | as written, on `os.name == "nt"` | elsewhere, `posix_build_harness` rewrites `harness.c` after `build_harness` writes it and before clang compiles it. It does this through a stand-in for `insn_test.subprocess` that is in place only during `build_harness`, so `main`'s run of the harness uses the real one. `posix_harness()` replaces the one `#include <windows.h>` and the one `VirtualAlloc(A64_MEM, …) … return 3;` line with `mmap` at `A64_MEM` (`0x1000_0000_0000`, `rt/a64.h`). If either text is not there exactly once, it stops with `SystemExit`, so an upstream change to the harness cannot make it silently do nothing |

On Linux, `toolchain.native_target()` and `native_link()` return `[]` (`third_party/a64-kit/tools/toolchain.py:54-71`),
so both harnesses build for the host with the flags they already had: `-mcx16` and `-O1`.

## How the Windows text was shown unchanged

- `tests/test_lifter_harness_posix.py` reads `HARNESS` from `nx2/test_leaf.py` without importing it (`ast`), and keeps
  only the `#ifdef _WIN32` branches. The result must equal `upstream/main`'s `HARNESS` byte for byte: compared directly
  through `git show upstream/main:nx2/test_leaf.py` when that remote is there, and always against its SHA-256
  (`246f5937…e29b`, from `upstream/main` `78e1112`). It holds on the Mac (both checks) and on the Deck (the hash; the
  Deck's copy has no git).
- The instruction test's Windows text is generated by `third_party/a64-kit/tests/insn_test.py` itself, and
  `git diff upstream/main -- third_party/ | wc -l` gives **0**. The new test also compares that file with
  `upstream/main`'s when git can.

## The new test

`tests/test_lifter_harness_posix.py`: 6 checks, standard library plus what is present.

| Check | Mac (arm64) | Deck container (x86-64 Linux) |
|---|---|---|
| leaf: the Windows branches equal upstream's | pass | pass |
| leaf: the POSIX branches have no `windows.h`, `VirtualAlloc`, `__try`, `__except`, `GetExceptionCode`, and have the `mmap`/signal pieces | pass | pass |
| leaf: compiled with 3 stand-in functions and run on 4 cases (return, bad address, illegal instruction, return): `(0, 0, 42)`, `(0, 0xC0000005, 0)`, `(0, 0xC000001D, 0)`, `(0, 0, 42)`, so a case after a fault still runs | skipped (Linux x86-64 only) | **pass** |
| insn: `posix_harness` turns the two Windows lines into POSIX ones and moves nothing else | pass | pass |
| insn: a harness without the include, without the line, or with two of them stops | pass | pass |
| insn: `build_harness`'s own `harness.c` (one stand-in encoding) made POSIX by the wrapper; on Linux x86-64 compiled and started on an empty input: exit 0, so the memory was mapped at `A64_MEM` | pass (no compile) | **pass** (compiled and run) |

It is not marked `RUN_ALL_SKIP`. The Linux-only parts skip by themselves elsewhere, and the instruction checks skip
where `nx2/test_insn.py` does not import (Unicorn, capstone or the lifter library missing).

### Forms by mnemonic

Re-sampled on the Mac with the same seed (1), `--per 6` and modules (main, subsdk0, sdk): the same 3,614 encodings
in 737 forms. That is **359 mnemonics**, 235 of the encodings being the Switch 2 additions (`insn.emit`). The
mnemonics with the most forms: `dup` 12, `ld1` 10, `st1` 9, `neg` 8, `movi` 8, `st2` 8, `ld4` 8, `add` 8, `cmhi` 8,
`st4` 8, `cmeq` 7, `ld3` 7, `shl` 7, `fmul` 7, `mov` 7. **Failures by mnemonic: none.**

### Failures by kind

None: no form, no function and no call tree differed. The cases Unicorn could not finish (it faulted, did not return
within 400,000 instructions, or touched an unmapped address) are skipped by design. In the call-tree run 354 of the
983 trees had no comparable case at all (983 − 629), and in the self-contained run 265 of 990 functions
(**inferred**: the test counts a root as run only when one of its cases was comparable). Those functions are untested,
not failed.

## What this means for M2

The lifter is verified on Raiders' own code for every instruction form it uses and for 1,354 functions run whole. So
T08's boot stop (`nn::pl::GetBuiltInFontData`, `M2-boot.md`) is a runtime matter, not a translation fault, and the same
holds for what T09–T11 find, unless a later run says otherwise.
