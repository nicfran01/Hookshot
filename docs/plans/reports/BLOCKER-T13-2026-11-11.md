## Options

1. **Add `nn::ngc` to T10 Part B's family list and implement it there** (`host/nn_offline.c`, which already has the
   offline-answer pattern). The offline answer would be:
   - constructor, destructor, `Initialize`, `Finalize`, `SkipAtSignCheck`: success, with no session;
   - `MaskProfanityWordsInText`: success, the text unchanged and 0 words masked in the count;
   - `CountNumbers`: count the ASCII digits (its documented behaviour, **inferred** from the name).

   **Cost:** one small HLE family, a relift (~3 min with the object cache) and a run through customization.
   **Risk:** low. The out-parameters must be checked against the callers by disassembly, as T10 did for `prepo`.
2. **A new small task "T13a: profanity filter offline"**, owned by T13's trace, with the same content as option 1.
   **Cost** as option 1, plus a task file. **Risk:** none beyond option 1.
3. **Answer `sm:`'s `GetServiceHandle` for `ngc:u` with a session whose requests succeed with zeroed output.**
   **Cost:** small, but it reaches into the shared IPC path. **Risk:** the SDK's `ngc` client reads its answers'
   layout, and zeroed output is unchecked (**unknown**). It is also against the runtime's HLE-first design.

## Recommendation

**Option 1.** `nn::ngc` is the same kind of offline system answer as T10 Part B's `prepo` and `err`, and T10 already
has the file, the tests' pattern and the disassembly method. Extend T10's ownership table with `nn::ngc` (and, while at
it, a row for "guest SDK reaching `sm:`", which the trace report cannot list), then run T10 Part B for it before T13's
next session.
